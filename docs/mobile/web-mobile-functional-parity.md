# Web ➔ Mobile Functional Parity Matrix

This document provides the authoritative, canonical functional parity matrix comparing the Tracker Next.js web application with the Tracker Android mobile application.

The web Tracker is the single source of domain truth. Mobile is a native client providing native interaction, local caching, and outbox mechanics without inventing duplicate or competing business rules.

---

## 1. Functional Parity Matrix

| Feature | Web behavior | Existing mobile behavior | Required mobile behavior | Reusable implementation | Status |
|---|---|---|---|---|---|
| **Google Authentication** | Initiates via `/api/auth/google`, checks PKCE, verifies Google ID token via JWKS, handles `source=mobile` redirecting to `tracker://auth-callback?token=...` | Username/PIN login form only | Google Sign In with deep link `tracker://auth-callback`, SecureStore session persistence, auto-restore | `/api/auth/google?source=mobile`, `/api/auth/callback/google`, `signSession`, `AuthService` | **IMPLEMENTED (Server ready) / MOBILE IN PROGRESS** |
| **Session Restoration & Lifecycle** | JWT in `tracker.session_token` cookie; validates `sessionVersion` & expiry; 401 on revocation | Token stored in SecureStore; verifies via `/api/mobile/v1/auth/me`; emits session expiration event | Silent cold-start session restore, auto-navigation to Today or Onboarding, secure logout purge | `SecureStore`, `trackerApi.me()`, `AuthService.resolveAuthFromRequest` | **TEST VALIDATED** |
| **Onboarding** | `OnboardingService` manages `NOT_STARTED` ➔ `IN_PROGRESS` ➔ `COMPLETED`; provisions first-day activity templates & occurrences | Direct entry to Today; skips onboarding checks | App launch checks onboarding state; if incomplete, guides through focus areas, capacity, objective; provisions first-day plan | `OnboardingService`, `DEFAULT_ONBOARDING_STATE`, `createFirstDayPlan` | **PLANNED** |
| **Today Dashboard** | Priority on actionable **TASKS** (`TodayTasks`), date navigation, WorkSession widget, Weight widget | Today with activity occurrence cards, WorkSession card, Weight card | Tasks as primary content; date navigation; checklist cycling; task context menu (Complete, Cancel, Postpone) | `generateTimeline`, `dashboardHelpers.ts`, `TodayTasks.tsx` | **IMPLEMENTED — RUNTIME UNVERIFIED** |
| **Activity Templates** | Recurring habit/task definition (`ActivityTemplate`) with category, type, recurrence, priority, targetDate | CRUD list with category pills, search, create modal, delete to Bin | Activity management native UI; editing targetDate for one-time tasks; color & category tags | `domain/validation.ts`, `TemplateService`, `/api/mobile/v1/activities/templates` | **TEST VALIDATED** |
| **Recurrence Analysis** | Computes due occurrences from RFC 5545 recurrence rules, daily/weekly/monthly/custom patterns, skipped dates | Pure domain UTC math in `domain/recurrence.ts` (`calculateNextDueDate`, `isActivityDueOnDate`) | Identical UTC date arithmetic and due-date evaluation | `lib/recurrence.ts`, `m/src/domain/recurrence.ts` | **TEST VALIDATED** |
| **Activity ➔ Task Generation** | `generateTimeline` produces `TimelineItem` occurrences for today: due templates + Google meetings + logged items | Filtered list of templates; manual occurrence generation | Reusable occurrence generator matching web `generateTimeline`: timed items first, anytime items by priority | `generateTimeline`, `dashboardHelpers.ts` | **TEST VALIDATED** |
| **Task State Machine** | Formal states: `pending` ➔ `done` ➔ `skipped` (Canceled) ➔ `postponed` (non-daily) ➔ `pending` | Checklist toggle cycle matching daily/non-daily rules | Strict adherence to `TaskStateMachine.isValidTransition` across all mutation pathways | `modules/activities/domain/TaskStateMachine.ts`, `m/src/domain/activity.ts` | **TEST VALIDATED** |
| **Task: Complete** | Clicking checkbox marks `done` (or `paid` for finance); creates/updates ActivityLog for date | Tap marks `done`; calls `/api/mobile/v1/activities/logs` | Tap checkbox completes task; optimistic local update + outbox mutation + sync | `ActivityService.logActivity`, `TaskStateMachine` | **TEST VALIDATED** |
| **Task: Cancel (Skip)** | Second tap or menu action marks `skipped`; log recorded with status `skipped` | Tap cycles to `canceled`; creates log | Cycles to `skipped`; skips occurrence for the date without deleting template | `ActivityService.logActivity`, `TaskStateMachine` | **TEST VALIDATED** |
| **Task: Postpone** | Non-daily tasks: log marked `postponed`, moves `nextDueDate` to tomorrow via `addUTCDays(1)`. One-time tasks: moves `targetDate` to tomorrow | Cycles to `postponed`; sets next day due | Non-daily: records `postponed` log, reschedules for next day. One-time: increments `targetDate` by 1 day | `lib/recurrence.ts`, `postponeOneTimeTaskAction` in `store.tsx` | **TEST VALIDATED** |
| **Task: Re-postpone / Restore** | Deleting/clearing the postponed log reverts recurring task to normal schedule. For one-time: reverts `targetDate` to original | Single-tap restore in Bin; cleared cycle resets status | Dedicated "Restore / Re-postpone" action returning task to previous schedule | `unpostponeOneTimeTaskAction` in `store.tsx`, `recurrence.ts` | **TEST VALIDATED** |
| **Calendar: Month View** | `CalendarAggregationService.getMonthSummary`: daily counts of tasks, Google events, worked hours, leave status | Not implemented | Native month grid displaying day indicators, task dots, worked hours badge, leave highlight | `CalendarAggregationService.getMonthSummary`, `/api/calendar` | **PLANNED** |
| **Calendar: Week View** | `CalendarAggregationService.getWeekView`: 7-day horizontal timeline with timed slots and all-day section | Not implemented | Native 7-day scrollable view with hourly schedule, task completion status, event source tags | `CalendarAggregationService.getWeekView` | **PLANNED** |
| **Calendar: Day View** | `CalendarAggregationService.getDayView`: detailed hour-by-hour agenda for selected date | Not implemented | Native full-day schedule with event details, location, task checklist, and work presence | `CalendarAggregationService.getDayView` | **PLANNED** |
| **Calendar: Today Jump** | Dedicated button jumps immediately to current local date | Not implemented | Single-tap "Today" button smoothly scrolling back to current date | Date domain helper | **PLANNED** |
| **Google Calendar Connection** | OAuth authorization granting Google Calendar scopes; creates `GoogleCredential` with encrypted refresh token | Not implemented | In-app Google Calendar connect action opening OAuth flow and storing credential on server | `/api/integrations/google-calendar`, `GoogleCredentialService` | **SERVER READY / MOBILE PLANNED** |
| **Google Calendar 2-Way Sync** | `CalendarService.sync`: incremental sync with `syncToken`; 410 error resets token & falls back to full sync | Not implemented | Mobile triggers server sync on demand or foreground; server handles two-way Google API reconciliation | `CalendarService.sync`, `GoogleCalendarProvider.ts` | **SERVER READY / MOBILE PLANNED** |
| **Linked Event Mapping** | `LinkedEventMapping` maps `googleEventId` ↔ `localLogId` with soft deletion and conflict timestamp | Not implemented | Server maintains stable mapping; mobile respects mapped items without generating duplicates | `LinkedEventMapping` model, `GoogleCalendarProvider` | **SERVER READY** |
| **Offline Cache** | React state only (web browser) | SQLite tables: `activity_template`, `activity_log`, `sync_state`, `mutation_queue` | Complete local read cache: tasks, events, and templates accessible without network | `expo-sqlite`, `db/database.ts` | **TEST VALIDATED** |
| **Mutation Outbox & Idempotency** | In-flight mutation locking and duplicate request filtering via client-assigned UUIDs | `mutation_queue` schema defined; atomic client IDs on logs | Local action persists to SQLite `mutation_queue` atomically; sync worker drains with retry | `db/database.ts`, `SafeSyncEngine` | **PARTIAL** |
| **Shared Bin (Data Recovery)** | Soft-delete on all models (`deletedAt != null`); restore updates `deletedAt = null` | `BinScreen` with module filter chips, single-tap restore via `/api/mobile/v1/bin` | Universal lifecycle: Delete ➔ Bin ➔ Restore or Irreversible Permanent Delete | `app/api/mobile/v1/bin/route.ts`, `BinScreen.tsx` | **TEST VALIDATED** |
| **Work Session Tracking** | Timer & manual mode; Office/WFH toggle; authoritative start timestamp invariant | `WorkSessionCard` with live ticking timer, Office/WFH, pause/resume/finish | Invariant preserved: entered start time anchors elapsed duration; server timestamps authoritative | `domain/work.ts`, `WorkSessionService.ts`, `WorkSessionCard.tsx` | **TEST VALIDATED** |
| **Weight Tracking** | Daily weight logging, 7-day history, automatic habit provisioning | `WeightWidgetCard` with 7-day row, decimal modal | Quick weight entry modal, validation (20-500kg), server parity | `WeightService`, `WeightWidgetCard.tsx` | **TEST VALIDATED** |
| **Settings & Account** | Profile, appearance, integrations, subscription status, data management | Profile card, direct Bin recovery card, local storage status, sign out | Profile details, Google Calendar connect status, offline sync toggle, cache purge, sign out | `SettingsScreen.tsx`, `/api/mobile/v1/auth/me` | **TEST VALIDATED** |
